# TAMEER Backend

FastAPI backend — the single source of truth for all business logic (estimation engine, rate database, auth, chatbot tool-calling). The web app and, later, the Android app are both thin clients of this API; no logic should be duplicated in either.

## Setup

Requires PostgreSQL running locally (`brew install postgresql@16 && brew services start postgresql@16`, then `createdb tameer`).

```bash
python3.12 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env           # then edit DATABASE_URL for your local setup
alembic upgrade head           # creates the users / saved_estimates tables
```

## Run

```bash
uvicorn app.main:app --reload
```

- API: http://localhost:8000
- Interactive docs (OpenAPI): http://localhost:8000/docs
- Health check: http://localhost:8000/api/v1/health

## Structure

```
app/
  main.py              # FastAPI app, CORS, router mounting
  core/
    config.py           # Settings (env-driven)
    security.py          # password hashing, JWT
  api/
    deps.py              # get_current_user, get_db
    v1/
      router.py           # aggregates all v1 routers
      endpoints/           # one file per resource — HTTP layer only
  schemas/               # Pydantic request/response models — the API contract
  db/
    base.py              # SQLAlchemy declarative base
    session.py            # async engine + session factory
    models/                # ORM models (User, SavedEstimate)
  domain/
    estimation/
      types.py             # shared enums (PlotSize, City, QualityGrade, ...)
      data.py               # ALL placeholder bylaw/ratio/rate numbers, isolated and heavily commented
      engine.py              # house estimate quantity-takeoff + pricing logic
      renovation_engine.py    # renovation estimate logic
    reports/
      pdf.py               # PDF report generation (reportlab)
alembic/                  # DB migrations — one revision per schema change, never edit an applied one
```

Every new feature gets its own router under `app/api/v1/endpoints/`, included in `app/api/v1/router.py`. Keep endpoint contracts (request/response models in `app/schemas/`) stable — the frontend and the future mobile app both depend on them.

**`app/domain/estimation/data.py` is placeholder data**, not verified figures — see the module docstring. When real bylaw/material-ratio/rate data is available, that file is the only thing that should need to change; the engine files should not.

## Auth

JWT bearer tokens, not session cookies — matches the API-first, multi-client (web + future mobile) architecture. `POST /api/v1/auth/register` and `/login` return a token; send it as `Authorization: Bearer <token>` on subsequent requests. Protected routes depend on `get_current_user` (`app/api/deps.py`).

## Database migrations

```bash
alembic revision --autogenerate -m "describe the change"   # after changing a model in db/models/
alembic upgrade head                                        # apply
```

Review every autogenerated migration before applying it — autogenerate doesn't always get it right (e.g. column renames show up as drop+add).
